    Three resources, three different problems — a security-critical voting system, a rules engine, and a small ML classifier.
    

      
    

        
        
    
          
          
    
            
    Biometric Voter Verification System — a group project built to explore what a booth-level identity and vote-integrity system actually requires under the hood.
    

            
    
              
    // the problem
    
              
    A polling booth needs more than "check a fingerprint and let someone vote." Officers need to be authenticated separately from voters. Every booth needs its own dashboard and audit trail. And the system has to make it structurally impossible for the same voter to be recorded twice — even if two booths query the same record seconds apart.
    
            
    

            
    
              
    // the approach
    
              
    I worked on the backend: REST APIs in Go covering officer login, voter lookup, booth dashboards, and audit logs, with Firebase Firestore behind it for real-time voter records and polling-booth data. Access control runs on JWT authentication with role-based access control, so an officer's token scopes exactly what that officer's booth is allowed to see or modify.
    
            
    

            
    
              
    // the key decision
    
              
    Duplicate-vote prevention was the part that couldn't be an afterthought. Vote validation runs as a transaction rather than a simple read-then-write — so a "check eligibility, then mark as voted" sequence can't be split by two concurrent requests hitting the same record. It's the same class of problem as double-spending in a ledger: correctness matters more than speed here, and the transaction boundary is where that gets enforced.
