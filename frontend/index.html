    /projects
    
      
    Three resources, three different problems — a security-critical voting system, a full-stack approval workflow, and a small ML classifier.
    

      
    

        
        
    
          
          
    
            
    Biometric Voter Verification System — a team hackathon project for the ECI (Election Commission of India), built around what a booth-level identity and vote-integrity system actually requires under the hood.
    

            
    
              
    // the problem
    
              
    A polling booth needs more than "scan a biometric and let someone vote." Officers need to be authenticated separately from voters. Every booth needs its own dashboard and an audit trail that shows tampering. And the system has to make it structurally impossible for the same voter to be recorded twice — even if two booths query the same record seconds apart.
    
            
    

            
    
              
    // the approach
    
              
    I built the backend: a Go (Gin) REST API with 6 endpoints covering Aadhaar + iris verification, the booth dashboard, and tamper-evident audit logs, with Firebase Firestore behind it. Access control runs on JWT authentication with role-based access control, so an officer's token scopes exactly what that officer's booth is allowed to see or modify.
    
            
    

            
    
              
    // the key decision
    
              
    Duplicate-vote prevention was the part that couldn't be an afterthought. Vote validation uses Firestore transactions and atomic counters across 4 collections rather than a simple read-then-write — so a "check eligibility, then mark as voted" sequence can't be split by two concurrent requests hitting the same record. It's the same class of problem as double-spending in a ledger: correctness matters more than speed here, and the transaction boundary is where that gets enforced.
    
            
    

            
    
              
    // protecting PII
    
              
    Aadhaar and iris data are stored as salted SHA-256 hashes rather than raw values, Firestore is restricted to backend-only access through security rules, and the service ships as a multi-stage Docker build.
